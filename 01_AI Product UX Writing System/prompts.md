# AI Product UX Writing System Prompts

### Content Layer: In-Product Experience

---

# Purpose

These prompts support scalable AI-assisted UX writing workflows.

The prompts are designed to:

* improve interaction clarity
* maintain tone consistency
* reduce ambiguity
* improve trust communication
* standardize AI messaging structures

This document simulates how mature product organizations operationalize AI-assisted UX content workflows across product teams.

---

# Prompt Architecture

The prompt system is structured around five operational goals:

| Goal        | Purpose                                         |
| ----------- | ----------------------------------------------- |
| Clarity     | Reduce ambiguity in AI interactions             |
| Trust       | Improve transparency and expectation management |
| Recovery    | Help users recover from failure states          |
| Consistency | Standardize language across product surfaces    |
| Scalability | Support reusable governance patterns            |

---

# Prompt 1 — UX Writing Clarity Evaluation

## Objective

Evaluate whether AI interaction copy clearly communicates:

* user expectations
* system behavior
* review requirements
* limitations
* recovery guidance

---

## Prompt

```plaintext
You are a senior UX content designer evaluating AI-assisted product interactions.

Review the following UX copy.

Evaluate:
- clarity
- ambiguity
- user expectations
- trust risks
- transparency
- actionability

Identify:
- vague phrasing
- misleading certainty
- missing recovery guidance
- inconsistent terminology

Then rewrite the content to improve:
- trust
- usability
- comprehension
- behavioral clarity

UX Copy:

[INSERT COPY]
```

# Prompt Governance Rules

## Never Allow

* fake certainty
* misleading automation claims
* unexplained AI actions
* robotic tone
* passive recovery guidance
* hidden AI behavior
* manipulative urgency
* blame-oriented messaging

# AI UX Writing Evaluation Matrix

Generated UX content should be evaluated against:

| Metric                  | Description                               |
| ----------------------- | ----------------------------------------- |
| Clarity                 | Can users understand the message quickly? |
| Trust                   | Does the message avoid overpromising?     |
| Recovery                | Is next action obvious?                   |
| Tone Consistency        | Does it align with system standards?      |
| Accessibility           | Is language simple and inclusive?         |
| Operational Consistency | Does it match shared terminology?         |
| AI Transparency         | Is AI behavior sufficiently explained?    |
| Escalation Readiness    | Can users recover or seek help easily?    |

---

# Prompt Failure Modes

Teams should monitor for the following failure patterns.

| Failure Mode                | Risk                          |
| --------------------------- | ----------------------------- |
| Overconfident AI language   | trust erosion                 |
| Generic error messaging     | increased support burden      |
| Inconsistent terminology    | fragmented product experience |
| Excessive technical jargon  | usability decline             |
| Missing escalation guidance | workflow abandonment          |
| Hidden automation logic     | compliance and trust risks    |

# Operational Workflow

## Step 1 — Define Interaction Context

Teams identify:

* workflow type
* AI involvement
* user intent
* risk level
* business sensitivity

---

## Step 2 — Select Prompt Category

| Prompt Category        | Use Case                   |
| ---------------------- | -------------------------- |
| Clarity Evaluation     | UX reviews                 |
| Error Generation       | recovery workflows         |
| Trust Messaging        | AI transparency            |
| Empty State Creation   | workflow initiation        |
| Onboarding Guidance    | first-use experiences      |
| Uncertainty Handling   | confidence-limited outputs |
| Terminology Validation | governance reviews         |

---

## Step 3 — Generate Draft Content

Teams generate initial outputs using structured prompts.

---

## Step 4 — Human Review

Human reviewers validate:

* clarity
* compliance
* accessibility
* tone
* trust implications
* terminology consistency

---

## Step 5 — Governance Approval

Approved content is aligned to:

* design systems
* content governance standards
* localization requirements
* AI disclosure policies
